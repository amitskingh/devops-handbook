### Branch Rulesets vs Classic Branch Protection (Short Note)

In **GitHub**, there are two ways to protect branches:

**1️⃣ Classic Branch Protection Rules (Legacy)**

* Applies one rule per branch pattern (e.g., `main`).
* Can require PRs, approvals, status checks, signed commits, etc.
* Simple and suitable for small projects.
* Limited flexibility — rules don’t stack well.

**2️⃣ Branch Rulesets (Modern System)**

* More flexible and powerful.
* Multiple rules can apply together.
* Can target branches, tags, repositories, or entire organizations.
* Better for teams and enterprise-scale projects.

**Summary:**
Classic rules are simpler but limited. Branch Rulesets are more advanced, scalable, and recommended for modern team workflows.
